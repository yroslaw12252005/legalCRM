# Интеграция с Tilda

Новый защищённый webhook работает параллельно со старым `/all-leads/tilda_lead/`, чтобы существующие формы можно было переключить без остановки.

После переключения всех форм старый endpoint отключается переменной окружения:

```text
TILDA_LEGACY_WEBHOOK_ENABLED=False
```

## Настройка

1. Войти в CRM администратором компании.
2. Открыть пункт меню «Интеграция с Tilda».
3. Создать отдельное подключение для формы или филиала.
4. Скопировать Webhook URL и показанный один раз API-ключ.
5. В Tilda открыть «Настройки сайта → Формы → Webhook».
6. Указать Webhook URL.
7. Настроить передачу ключа: `Header`, имя `X-Tilda-Token`, значение — API-ключ CRM.
8. Включить Webhook у нужного блока формы и опубликовать страницу.

Компания и филиал берутся только из настройки подключения. Значения `id_company`, `id_felial` и `felial_id`, присланные формой, игнорируются.

## Поддерживаемые форматы

- `application/x-www-form-urlencoded`
- `multipart/form-data`
- `application/json`

Максимальный размер запроса — 256 КБ. Поля имени, телефона, почты и комментария настраиваются для каждого подключения. Если задан список разрешённых `formid`, остальные формы отклоняются.

## Защита от дублей

Основной ключ идемпотентности — `tranid`. Если его нет, используется хеш формы. Повторное обращение возвращает `200 ok`, но второй лид не создаётся. Сохраняется только минимальный ключ дедупликации и ссылка на созданный лид; сырые обращения и журнал запросов не сохраняются.

## Замена ключа

После замены новый ключ показывается один раз. Старый ключ продолжает работать 10 минут, чтобы форму можно было переключить без потери заявок.

## Ответы

- `200 ok` — тест, новая заявка или безопасно распознанный дубль;
- `400` — некорректные данные или запрещённый `formid`;
- `403` — неверный API-ключ;
- `404` — подключение отсутствует или отключено;
- `413` — запрос больше допустимого размера;
- `415` — неподдерживаемый формат;
- `429` — превышен лимит запросов.
